# Pokemon Aegis — UI 디자인 시스템

이 문서가 UI의 단일 기준이다. 새 화면을 만들거나 기존 화면을 고칠 때 여기에
적힌 것만 쓴다. 여기 없는 색·크기·효과를 파일에 직접 쓰지 않는다.

## 왜 이렇게 정했나

리뷰에서 "AI가 디자인한 것 같다"는 지적이 반복됐다. 원인을 코드로 추적한 결과
취향 문제가 아니라 구체적인 관용구들이었다.

- 색 리터럴 2,601개 / 고유 hex 363종이 팔레트 없이 화면마다 따로 만들어져 있었다.
  골드가 6종, 파랑이 6종, 본문 흰색이 5종. 사람은 이 어긋남을 색으로 집어내진
  못해도 "싸구려"로 느낀다.
- 폰트가 시스템 스택 하나뿐이었다. 게임인데 게임 폰트가 없었다.
- `public/` 에 UI 아트 에셋이 0개였다. UI 전체가 CSS 프리미티브로만 만들어져
  있었다 — 프레임도, 텍스처도, 스프라이트도 없이. **이게 근본 원인이고 나머지는
  증상이었다.**
- 전역 규칙이 모든 버튼을 hover 시 `translateY(-3px)` + 파란 글로우 + 300px
  머티리얼 리플로 띄우고 있었다.
- 맵과 포켓몬은 도트인데 그걸 감싼 껍데기는 웹 관리자 페이지였다. 둘 중 하나가
  거짓말을 하고 있었고, 리뷰어는 그걸 "AI 같다"라고 불렀다.

기준으로 삼은 것은 **포케로그(pokerogue.net)** 다. 그 UI에서 가져온 원칙은 셋이다.

1. **창 채움은 고정, 테마는 테두리만 바꾼다.** 포케로그의 window type 정의를 보면
   `--color-base` 가 전 테마 공통이고 `--color-light` 만 테마별로 다르다. 버튼마다
   채움색을 바꾸면 화면이 "색 덩어리 목록"이 된다.
2. **글자에 블러 없는 하드 그림자를 넣는다.** 포켓몬 UI 글자는 예외 없이 이걸 달고
   있고, 없으면 도트 폰트를 써도 웹 텍스트로 읽힌다.
3. **모든 치수가 정수 배율이다.** 도트는 정수 배율에서만 선명하다.

> **라이선스** — 포케로그는 AGPL-3.0-only 이고 에셋은 원본 리핑 서브모듈이다.
> 코드나 PNG를 가져오면 이 프로젝트까지 전염된다. 구조와 색만 참고해 우리
> 생성기로 다시 그렸다. **앞으로도 그쪽 파일을 복사해 오지 않는다.**

## 색

패널 면은 **딥 슬레이트 네이비**. 채도를 낮게 유지하는 게 핵심이다. 이 게임 앞에는
1025종 스프라이트가 온갖 색으로 올라오고 맵은 초록·황토·파랑이라, 패널이 채도를
가지면 어떤 타입 색과는 반드시 충돌하고 스프라이트가 묻힌다. **정체성은 면이 아니라
테두리 액센트와 골드가 진다.**

| 역할 | 값 | 쓰는 곳 |
|---|---|---|
| `bg` | `#232a3d` | 페이지 배경 (맵 위 스크림) |
| `panel` | `#39415c` | 창 안쪽 채움 |
| `panelBtn` | `#4a5372` | 버튼 채움 |
| `panelSunk` | `#2c3348` | 파인 면, 모달 헤더/푸터 띠 |
| `ink` | `#161b28` | 창틀 바깥 외곽선, 글자 그림자 |
| `divider` | `#5c6684` | 구분선 |
| `text` / `textSub` / `textDim` | `#ffffff` / `#cfc4d8` / `#9a8ea6` | 본문 / 보조 / 비활성 |

액센트 9종: `plain` `red` `teal` `gold` `blue` `purple` `green` `cyan` `navy`.
브랜드 색은 **골드**(`#ebc07c`) — 재화색이자 제목 색.

포켓몬 타입 색은 `TYPE_COLOR` 표를 쓴다. Tailwind 팔레트로 타입 색을 흉내내지
않는다. 그게 "포켓몬 같지 않다"의 원인 중 하나였다.

### 팔레트를 따로 만들지 말 것

같은 개념의 색이 파일마다 다르게 정의되는 게 이 프로젝트의 원래 병이었다(고유 hex
363종). 특히 **자기 팔레트를 들고 있기 쉬운 세 자리**는 전부 토큰으로 위임해 두었다.
새로 만들 때도 여기로 붙인다.

| 자리 | 규칙 |
|---|---|
| `utils/typeEffectiveness.ts` `getTypeColor()` | `TYPE_COLOR` 위임 |
| `components/game/GameCanvas.tsx` `typeColor()` | `TYPE_COLOR` 위임 — 캔버스도 예외 아님 |
| `components/shared/Emoji.tsx` 아이콘 색 | 겹치는 색은 `tokens.C` 에서 가져오고, 대응 없는 색만 확장 |

캔버스가 특히 함정이었다. 테라 타일은 캔버스가 칠하고 그 타일을 설명하는 툴팁은
DOM이 칠하는데, 팔레트가 갈라져 있으면 **같은 타일이 두 색으로 보인다.**
아이콘도 같다 — 골드 코인 아이콘과 그 옆 골드 글자가 다른 금색이면, 하나하나는
안 보여도 화면 전체가 정돈이 안 된 느낌을 준다.

### ⚠ 값 동기화

`ink` / `panel` / `panelBtn` / `panelSunk` 는 **창틀 PNG에도 구워진다.**
`genUiFrames.mjs` 의 `INK` / `FILL_WIN` / `FILL_BTN` / `FILL_IN` 과 반드시 같아야
하고, 어긋나면 같은 패널 안에서 색이 갈리는 이음매가 보인다.

팔레트를 고쳤으면:

```bash
npm run ui:frames && npm run ui:check
```

## 타이포

**12px이 하한, 그 위로는 4px 격자.**

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `FONT.sm` | 12px | 본문·라벨. 도트 폰트 하한 |
| `FONT.md` | 16px | 화면 제목·카드 제목·강조 본문 |
| `FONT.lg` | 20px | 패널 제목 |
| `FONT.xl` | 24px | 큰 제목·주요 수치 |
| `FONT.xxl` | 32px | 결과 화면 점수 등 |
| `FONT.display` | 36px | 연출용 최대치 |

예전에는 12 / 24 / 36 세 칸뿐이었다. 제목과 본문 사이가 비어 있어 **화면 글자의
92%가 12px 한 크기로 눌렸고**(sm 588회 : base 40회 : lg 13회), 그 틈을 토큰 밖
리터럴(14·18·20·22px)이 몰래 메우고 있었다. 위계가 없으면 화면이 평평해 보인다 —
도트 UI라서가 아니라 스케일이 없어서 생기는 문제였다.

**아이콘 크기는 `ICON`(12/16/20/24)을 쓴다.** 아이콘은 글자가 아니다. 이 토큰이
없던 시절에는 아이콘 치수가 `font-size: 18px` 꼴로 타이포 스케일에 섞여 들어왔다.

`ICON` 보다 큰 장식 글리프(빈 목록의 48px 이모지 등)는 토큰이 없다. 글자가 아니라
그림이므로 타입 스케일에 넣지 않고, 4px 격자만 지킨다.

### 글자 그림자

`pixelText` 가 **1px**을 깐다. 24px 이상 큰 글자에는 `shadowLg`(3px)를 덧씌운다.

기본값이 3px이던 시절에는 호출부 324곳이 손으로 1px로 덮어쓰고 있었고, 덮어쓰지
않은 352곳은 12px 글자에 3px 그림자가 붙어 획 사이가 메워져 있었다. **같은 크기
글자의 그림자가 파일마다 달랐다** — 토큰의 기본값이 다수 케이스와 반대라서 생긴 일이다.

## 글꼴

**Galmuri11** (SIL OFL 1.1, 자체 호스팅 `public/fonts/`). 한글 음절을 커버하는
도트 폰트가 사실상 이것뿐이라 폴백은 최후 수단이다.

크기 표는 위 **타이포** 절에 있다. 13px·12.5px 처럼 4px 격자를 벗어난 값을 쓰면
도트가 뭉개진다.

두 가지가 필수다.

- `-webkit-font-smoothing: none` — 안티에일리어싱이 켜져 있으면 글자 가장자리에
  회색 반픽셀이 생겨 도트가 흐물흐물해진다.
- 블러 0의 하드 그림자 — `pixelText` 가 1px을 깔고, 큰 글자만 `shadowLg`(3px).

행간은 `pixelText` 가 `line-height: 1.5` 를 준다. 브라우저 기본값(`normal`)은
Galmuri 메트릭에서 글자 위아래가 잘려 보인다 — 받침 있는 한글과 괄호·슬래시가
특히 깎인다. 고정 높이 컨트롤을 만들 땐 이 1.5를 계산에 넣는다.

전부 `pixelText` / `pixelBold` 에 들어 있으니 직접 쓰지 말고 믹스인을 쓴다.
(`pixelSmall` 은 없앴다 — 기본값이 1px이 되면서 `pixelText` 와 같아졌다.)

## 간격

세로 여백은 가로보다 넉넉하게 준다. 12px 글자에 행간 1.5(=18px)가 붙으므로,
가로와 같은 값을 세로에 주면 글자가 칸을 꽉 채워 답답해 보인다.

`win()` `btn()` `btnThin()` `winThin()` `sunken()` 이 **여백의 바닥을 깔아 둔다**.

| 믹스인 | 기본 padding |
|---|---|
| `win()` | 12px |
| `btn()` | 8 / 12 |
| `btnThin()` `winThin()` `sunken()` | 4 / 8 |

호출부가 `padding` 을 다시 주면 덮어쓴다. **덮어쓸 때 세로를 0으로 두지 말 것** —
배지든 버튼이든 최소 `SP.xs`(4px)는 남긴다. 고정 `height` 를 줄 때도 창틀 두께 +
여백 + 행간의 합보다 작으면 글자가 눌린다(얇은 창틀 기준 6+4+18+4+6 = 38px).

## 화면 껍데기

라우트 화면(모달이 아닌 것)은 `src/components/shared/screen.tsx` 를 쓴다.

| 컴포넌트 | 역할 |
|---|---|
| `Screen` | 배경·글꼴·세로 배치 |
| `ScreenTopBar` | [뒤로]·[제목]·[우측 슬롯] 3분할 상단 바 |
| `ScreenBackBtn` `ScreenTitle` `ScreenSpacer` | 상단 바 조각 |
| `ScreenBody` | **화면 여백의 단일 출처.** `$narrow` 로 읽기 폭(620px) |
| `SectionLabel` `EmptyState` | 본문 구획 제목 · 빈 목록 |

**여백은 화면이 정하지 않는다.** 예전엔 같은 역할의 조각이 화면마다 따로 선언돼
있었고(`Root` 17곳 · `Title` 16곳 · `TopBar` 10곳 · `BackBtn` 11곳), 색은 토큰에서
왔으니 안 갈렸는데 **여백 조합이 갈렸다.** 실측한 본문 여백이 다섯 가지였다:

```
xl lg xxl   xl md xxl   lg md xxl   xl lg   lg lg xl
```

좌우가 16px인 화면과 12px인 화면이 섞여 있어 화면을 오갈 때 내용 좌변이 흔들렸고,
상단 바는 태블릿 브레이크포인트가 있는 화면과 없는 화면이 섞여 iPad에서 헤더 높이가
달랐다. 예외가 필요하면 `styled(ScreenBody)` 로 덧쓰되, **그건 예외라는 뜻이다.**

브레이크포인트도 파일마다 `const L1024 = lMedia.tablet` 로 다시 만들지 않는다.
이름이 픽셀값이라 `responsive.utils` 의 실제 값이 바뀌면 거짓말이 된다.

## 창틀

CSS가 아니라 **PNG 나인슬라이스**다. `border-radius` 로 흉내내면 모서리가
안티에일리어싱된 곡선이 되어 즉시 "웹 카드"로 읽힌다. 창틀의 정체성은 모서리가
픽셀 계단이라는 점이다.

구조는 바깥에서 안으로: **검은 외곽선 1 → 액센트 2겹 → 어두운 액센트 1 → 채움.**

두께는 두 종류다.

| | 테두리 | 쓰는 곳 |
|---|---|---|
| `win()` / `btn()` | 12px | 창, 모달, 큰 버튼 |
| `winThin()` / `btnThin()` | 6px | X 닫기, 로그아웃, 가이드 버튼, 배지 |

**작은 컨트롤에 `btn()` 을 쓰지 말 것.** 44×36 버튼에 12px 테두리를 씌우면 가로
44 중 24가 테두리라 납작한 컨트롤이 아니라 부풀어 오른 덩어리로 보인다. 포케로그도
같은 문제를 `WindowVariant(NORMAL/THIN/XTHIN)` 로 푼다.

얇은 창틀은 세로 여백을 `padding` 으로 직접 줘야 한다. 테두리가 6px뿐이라 `0` 으로
두면 글자가 위아래에 붙는다.

## 버튼

- **게임 버튼은 눌리지, 떠오르지 않는다.** hover 에서 이동·확대·글로우 금지.
- 눌림은 테두리 명암이 뒤집히는 것(`-in` 텍스처)으로만 표현한다. 아래에 `box-shadow`
  로 검은 줄을 깔지 않는다 — 도트 테두리 밑에 생짜 검은 선이 하나 더 그어져
  그림자가 아니라 오류처럼 보인다.
- **닫기·로그아웃 같은 이탈 버튼에는 창틀을 씌우지 않는다.** 배경도 테두리도 없이
  글리프(`✕`)나 글자만 두고, 기본 `textDim` → hover `text` 로만 반응한다. 테두리를
  두르면 작은 컨트롤이 부풀어 올라 정작 제목보다 먼저 눈에 들어온다. 닫기 글리프는
  빨간 ❌ 이모지가 아니라 `✕` 문자를 쓴다 — 이모지는 오류 아이콘으로 읽힌다.
- 선택 표시는 `cursorMark` / `cursorOn` — 포켓몬 메뉴의 ▶ 포인터. hover 글로우
  대신 이걸 쓴다. 커서는 창 **안쪽** 왼편에 놓고, 호출부가 `CURSOR_GUTTER` 만큼
  `padding-left` 로 자리를 비운다.

## 모달

`modal.styles.ts` 의 껍데기만 쓴다. 직접 만들지 않는다.

- `ModalBox` 의 `$accent` 는 hex 가 아니라 **창틀 이름**(`MODAL_ACCENT.gold` 등).
- **제목은 짙은 머리띠 위에 얹히고, 머리띠는 창틀 안쪽 끝까지 닿는다.** 창틀이
  사방 `FRAME_W`(12px)를 먹으므로, 머리띠를 그 안에 얌전히 넣으면 창틀과 머리띠
  사이에 창 바탕이 12px 띠로 남아 붕 떠 보인다. 음수 마진으로 사방을 당기고,
  당긴 만큼 패딩으로 되돌린다. 한때 위만 당기지 않던 시절이 있었는데, 그때 문제는
  당긴 것 자체가 아니라 패딩이 12px 그대로여서 제목이 모서리에 박힌 것이었다.
- **좌우 여백은 `modalPadX` 하나에서만 온다.** 창 자신이 이미 12px을 갖고 있고
  그 위에 `modalPadX`(16px, 좁은 화면 12px)가 얹혀, 글의 좌변은 창틀 안쪽에서
  **28px**(좁은 화면 24px)이 된다. 머리띠는 창틀 밖으로 나가 있으므로
  `calc(FRAME_W + MODAL_PAD_X)` 로 같은 좌변에 선다.
  **본문이 머리띠보다 좁으면 안 된다.** 예전에는 머리띠·탭 줄·본문·표가 저마다
  값을 정해, 업적은 탭이 제목보다 왼쪽으로 튀어나오고, 자료실은 표가 창틀에 붙고,
  전당은 좁은 화면에서만 본문이 8px로 좁아졌다. 값이 아니라 출처가 하나여야 한다.
- **층위가 다른 줄에는 다른 크기를 쓴다.** 주 탭은 `ModalTabBtn`(두꺼운 창틀 +
  16px), 그 안을 걸러내는 필터는 `ModalChipBtn`(얇은 창틀 + 12px). 전당의
  [최단 클리어 | 최고 웨이브 | 내 기록] 아래에 [전체 맵 | …] 이 같은 얇은 칩으로
  붙어 있던 시절, 두 줄이 한 덩어리로 읽혔다. 색만으로는 갈리지 않는다 — 둘 다
  '선택된 것만 금색'이라 규칙까지 같아 보이기 때문이다.
- **가로로 스크롤하는 줄에는 여백을 직접 주지 않는다.** 스크롤 상자 자신의 padding
  은 내용과 함께 밀려서, 조금이라도 스크롤하면 첫 항목이 창틀에 붙어 잘린다.
  `ModalScrollRowPad` 로 감싸 **여백은 바깥이, 스크롤은 안쪽이** 맡게 한다.
- **창은 두 계열이다.** 큰 창(업적·전당·랭킹·자료실 등)은 안쪽에 스크롤 상자를 두고
  그 상자가 `modalPadX` 를 갖는다. 확인 대화상자·픽커·결과창은 그 상자가 없어 내용이
  창에 직접 놓이므로, `ModalPlainBox` + `ModalPlainHeader` 를 써서 **창 자신이** 같은
  좌변(28px, 좁은 화면 24px)을 만든다. 두 계열의 글 좌변은 같은 값이다.
  예외는 `SkillPicker` 하나 — 300px 고정 사이드 패널이라 28px을 주면 기술 이름이
  들어갈 폭이 244px까지 눌린다. 규칙(띠는 창틀에 붙고 제목은 본문과 같은 좌변)은
  같고 값만 그 창의 여백(12px)을 따른다.
- 자료실(`GameDocs`)에 **소스 파일 경로를 쓰지 않는다.** 데이터의 `src` 필드는
  수치를 고칠 때 어디를 열지 적어 둔 개발용 메모이고, 화면에는 나가지 않는다.
- 오버레이에 `backdrop-filter` 를 쓰지 않는다. 단순 딤만.
- `ModalHeader` 의 `-FRAME_W` 좌우 확장은 **큰 모달에서만** 쓴다. 200px 남짓한
  작은 창(인게임 햄버거 메뉴 등)에 같은 방식을 쓰면 띠가 창틀 밖으로 삐져나온다.
  작은 창은 마진 없이 창틀 안쪽만 채운다.

## 배경

`backdrop(map)` — 게임 맵 썸네일(480×320, 10~20KB)을 `pixelated` 로 확대하고
스크림을 86% 덮는다. 장식용 파티클 대신 실제 게임 자산을 쓴다. 확대된 도트가
오히려 의도된 질감으로 읽힌다.

## 금지 목록

리뷰가 지적한 인상의 직접적 원인들. 새로 만들지 않는다.

| 금지 | 대신 |
|---|---|
| `rgba(255,255,255,0.0x)` 유리 카드 + 반투명 1px 테두리 | `win()` / `btn()` |
| `backdrop-filter: blur()` | 불투명 면 |
| hover 시 `translateY(-)`, `scale()`, 글로우 | `cursorMark` |
| eyebrow (11px/700/`letter-spacing:0.2em`/uppercase) | `SectionLabel` 같은 목록 머리글 |
| 한글 UI 속 영문 대문자 배지 (`EASY` `HARD`) | 한글 라벨 |
| `→` 화살표 장식 | ▶ 커서 |
| 기능 카드 (둥근사각 아이콘칩 + 제목 + 회색 부제 + 화살표) | 창틀 버튼 |
| Tailwind 기본 팔레트 (`#3b82f6` `#10b981` `#f59e0b` `#c084fc` `#22d3ee`) | `C` 토큰 |
| `border-radius` 로 만든 둥근 모서리 | 창틀 PNG |
| 번지는 그림자 (`box-shadow` 에 blur) | 하드 그림자 또는 없음 |
| 12px 미만·4px 격자를 벗어난 폰트 크기 | `FONT` 스케일 |

## 인게임 화면의 제약

인게임은 가로 전용 3분할(좌 시너지·HUD / 중앙 맵 / 우 상점·액션)이고, 좌우 패널
폭이 곧 글자 크기의 상한이다. 예전에는 폰 가로에서 패널을 128px까지 줄이고 글자를
6~8px로 낮췄는데, **도트 폰트는 12px 미만에서 읽히지 않는다.** 그래서 폭을 늘리고
글자를 12px에 고정하는 쪽으로 뒤집었다.

| | 패널 폭 | 액션 버튼 |
|---|---|---|
| 데스크탑 | 216px | `btn()` 12px 창틀, 높이 80 |
| 태블릿 가로 (≤1024) | 180px | 같음. 라벨 뒤 보유 수(`LblSub`)는 숨김 |
| 폰 가로 (≤768) | 152px | `btnThin()` 6px 창틀, 높이 48, 아이콘 숨김 |

폰 가로에서 12px 창틀을 유지하면 버튼 한 칸 70px 중 24px이 테두리라 글자가 들어갈
자리가 없다. 좁아지면 **글자를 줄이는 게 아니라 창틀을 얇게** 한다.

맵 위 툴팁은 `CenterPanel`(`overflow: hidden`) 안에 있으므로 커서가 아래 절반이면
위로, 오른쪽 60% 밖이면 왼쪽으로 뒤집는다(`tooltipPos`). 안 그러면 잘린다.

## 마이그레이션 현황

**전 화면 완료.** 51개 파일이 이 시스템을 쓴다 — 메인메뉴 · 로그인 · 인게임
(HUD·상점·시너지·캔버스 오버레이) · 맵선택 · 스토리(선택·오프닝·엔딩) ·
미니 포켓 8종 · 퀴즈 4종 · 멀티 5종 · 모달 13종(자료실 포함) · 토스트 ·
인증 로딩 화면.

`components/` 아래 **모든 파일**이 토큰·믹스인·모달 스타일 중 하나 이상을 쓴다.
아이콘 매핑 표(`shared/Emoji.tsx`)와 인증 로딩 화면(`auth/ProtectedRoute.tsx`)처럼
styled 컴포넌트가 거의 없는 자리도 색은 토큰에서 가져온다.

확인:

```bash
grep -rL "styles/tokens\|styles/pixel\|modal.styles" --include=*.tsx src/components
```

색 리터럴은 `tokens.ts` 로 모였다. 타입 색은 `TYPE_COLOR` 한 곳이 단일 출처이며
`utils/typeEffectiveness.ts` 의 `getTypeColor()` 가 여기로 위임한다.

### 의도적 예외

세 곳은 도트 문법을 따르지 않는다. 장르 관습이 더 강한 자리라서다.

| 자리 | 남긴 것 | 이유 |
|---|---|---|
| `CardView` | 3D 기울기·광택·홀로그램 | 미니 포켓은 '트레이딩 카드'가 소재다 |
| `PackOpening` | 섬광·카드 뒤집기 | 팩 개봉은 이 모드의 핵심 연출 |
| `BossCutIn`, `StoryOpening/Ending` | 사선 그라디언트·캐릭터 아트 | 컷인/비주얼 노벨 연출 |

이 자리들도 **글자와 색은 토큰을 쓴다.** 예외는 연출 레이어에만 적용된다.

### 남은 것

- `GameCanvas` 의 프렌들리숍 창은 공유 `modal.styles` 를 못 쓰는 자리(캔버스 안
  오버레이)라 창틀 믹스인을 직접 적용했다. 나중에 공용 컴포넌트로 뽑을 여지가 있다.
- `TutorialModal` 은 모드별 액센트를 아직 그라디언트 리터럴로 들고 있다
  (`linear-gradient(135deg,#0284c7,#0369a1)` 등 4쌍). 창틀·글자는 토큰을 쓰므로
  화면상 어긋나 보이진 않지만, 액센트를 바꿀 때 고쳐야 할 자리가 하나 더 있는 셈이다.
- 지도 카드의 hover 덧칠(`MapSelector`)과 비주얼 노벨 텍스트 박스의 얇은 구분선은
  반투명 흰색 리터럴로 남아 있다. 둘 다 사진/연출 위에 얹히는 자리라 토큰 면색이
  맞지 않아 그대로 뒀다.

## 화면 확인

빌드가 통과했다고 화면이 멀쩡한 건 아니다. 창틀이 삐져나오거나 글자가 잘리는 건
눈으로만 보인다. `npm run shots` 가 dev 서버를 돌며 주요 화면을 `shots/` 에 PNG로
남긴다(이름을 인자로 주면 그 화면만, `이름@mobile` 이면 좁은 화면으로).

```bash
npm run dev          # 먼저 띄워 둔다 (5180)
npm run shots        # 전체
npm run shots docsQuiz menu@mobile
```

로그인이 필요한 화면(멀티 로비·속도전 방)은 localhost가 API 키 리퍼러 제한에
막혀 못 찍는다 — 배포본에서만 확인할 수 있다.
