# Pokemon Aegis 밸런스 문서 (v2.14 확정)

최종 갱신: 2026-07-12. 이 문서가 밸런스 수치의 **단일 출처 요약본**이다.
수치의 실제 정의는 각 항목에 표기된 소스 파일이며, 수치를 바꾸면 이 문서도 함께 갱신한다.
검증 도구: `npm run sim` (사다리·멀티 몬테카를로, [sim/README.md](../sim/README.md)).

---

## 1. 난이도 목표 (설계 앵커)

**아는 유저의 판당 승률**이 난이도 사다리의 정의다:

| 난이도 | 목표 승률 | 봇 시뮬 눈금* | v2.14 봇 실측 |
|---|---|---|---|
| easiest | 99% | 95% | **100%** ✓ |
| easy | 80% | 70% | **83%** ✓ |
| medium | 50% | 30% | **33%** ✓ |
| hard | 20% | 10% | 0% (p50 w8) |
| extreme | 1% | 1% | 0% ✓ |

\* 봇은 인간 테크(도구·시너지 완성·전설 스왑)를 다 못 쓰므로 하향 눈금으로 판정
(`sim/single/single.sim.ts TARGET_CLEAR`). hard 미달은 봇 한계로 진단(분리 2경로 = 실효
DPS 요구 ×2 ≈ medium +13웨이브 선행) — 밸런스 레버가 아님.

## 2. 적 스케일링 — `src/game/WaveSystem.ts`

| 항목 | 값 | 비고 |
|---|---|---|
| 적 수/웨이브 | `floor(5 + 1.5×wave)` | w1=6, w20=35, w50=80 |
| 지수 성장 (싱글/멀티) | **1.07^(wave-1)** | HP·공격 공통. w50 = 27.5× |
| 지수 성장 (스토리) | **1.08^(wave-1)** | 챕터 밸런스가 1.08 기준 튜닝됨 |
| 난이도 배율 (hp·attack) | easiest **0.4** / easy **0.55** / medium **0.7** / hard **0.85** / expert **1.0** | medium 앵커, 0.15 등간격 |
| 난이도 배율 (reward) | 0.8 / 0.9 / 1.0 / 1.1 / 1.2 | 고난도에 골드 이득 |
| 스토리 챕터 배율 | ch1~8: 0.6 → 0.9 (2챕터당 +0.1) | reward 1.0 고정 |
| 보스 | 3의 배수 웨이브, 몹수 **+1로 추가** 스폰 | HP ×4·스탯 ×2·이속 40·통과 시 −3 라이프 |
| 스토리 최종보스 (w30) | HP ×6·스탯 ×3·이속 20·−10 라이프 | 챕터 고정 에이스 |
| 적 기술 위력 | 기본 40 + 타입상성 + 스플래시(100px, 30%) | v1.23에서 20→40 |
| 적 위협 반경 | 160px (range 80 × 2) | 타워 사거리 192px(3타일) |

**1.07 확정 근거**: 타워 자연 성장 +5%/레벨보다 약간 가파르게 잡아, 기술 위력 상승(후반
100~120)·시너지·도구·테라·전설 스왑으로 벌충해야 이기는 기울기. "도구를 챙긴 만큼만
이긴다." v1.23 시절 medium 체감("딱 좋았다")을 배율 0.7 기준으로 근사.
실험 이력: 1.08(봇 easiest 58%) → 1.06 → 1.05(easy 75%지만 후반 무긴장 — 봇 저활용에
맞춘 착시로 판정) → **1.07 확정**. 1.07은 역사상 최초 사용(과거 1.1 → 1.08만 존재).

## 3. 아군 성장 — `src/store/gameStore.ts`

| 항목 | 값 | 비고 |
|---|---|---|
| 레벨업 XP | **플랫 100/레벨** | v2.6 티어드 곡선(구간당 +100) 폐기, v2.14 복원 |
| 레벨업 성장 | **전 스탯 +5%** (복리), 속도 고정 | `addXpToTower` |
| 킬 XP | 일반 10 / 보스 50 — **생존·비알바 전원**에게 각각 지급 | `GameManager.killEnemy` |
| 만렙 | 100 | |

**의도된 메타**: 50웨이브 자연 킬XP ≈ 22,400 → **w33쯤 전원 만렙**. 이후 낡은 타워를
하나씩 팔고 새로 사서 경험사탕으로 즉시 캐치업하는 **스왑 순환**(왕귀형·전설 수집)이
권장 플레이. 티어드 곡선은 이 순환을 죽여서 폐기했다(요구 54,000 XP = 만렙 불가).

공유 XP의 귀결: **6마리 조기 확정(≈w7)이 후반 생존의 결정 변수** — 늦게 합류한 유닛은
레벨 빚을 지지만, 플랫 100 + 경험사탕으로 캐치업 가능(스왑 순환의 전제).

## 5. 시너지·테라·도구·알바

- **타입 시너지** (`utils/synergyManager.ts`): 같은 타입 2/4/6마리 = 스탯 ×1.1 / ×1.3 /
  ×1.3+해당 타입 약점 피해 0.5배. 세대 시너지: 2마리 ×1.1, 6마리 ×1.3. PvE·PvP 모두 적용.
- **테라 타일** (`data/maps.ts`): 점유 타워의 타입을 타일 타입으로 변환(자속+방어상성).
  맵별 고정 타입, 위치는 N웨이브마다 spots 순환. 단일타입 6각+테라가 고수 메타.
- **알바**: 유닛을 시설 타일에 파견(전투 이탈, XP 미수령). 근무 5/10/15웨이브로 등급 해금.
  - 프렌들리숍(점원): 지닌도구 상점 (`data/heldItems.ts` — Lv1 열매/Lv2 딜템 ×1.06~1.1/
    Lv3 조개껍질방울 흡혈 8%·생명의구슬 ×1.12 등, 유나이트 수준의 부가 효과).
  - 콘테스트 홀(스카우트): 픽커 고레어 가중 부스트 (0.3/0.8/1.5).
- **배치**: 자유배치 — 길·입출구 keepout 3칸 제외 전 타일, 일직선 3연속 금지.
  (buildZones/울타리 시스템은 v2.8 폐기, v2.14에서 죽은 데이터 완전 제거.)

## 6. 멀티플레이 배틀 보상 — `src/services/battleRewards.ts`

- 승리: 기본 40G + 연승(2/3/4연승: +15/+30/+50) + 아군 3마리+ 생존 +20.
- 패배: 라이프 −(3+상대 생존 수). 위로금: 연패(2/3/4/5연패: 60/100/150/200G)
  + 저라이프 보정(≤20: +30, ≤10: +60).
- AI 상대(`services/AIPlayer.ts`)는 실플레이어 성장을 미러링: 웨이브 킬XP(몹수×10, 보스
  +50)를 100XP/레벨로 환산 × 난이도 효율(easy 0.4 / medium 0.7 / hard 1.0), 성장률도
  플레이어와 동일(전 스탯 +5%, 속도 고정). v2.14에서 확률 레벨업(수 배 느림)을 교체.

## 7. 밸런스 변경 절차

1. 변경 전 `npm run sim`으로 현 수치 측정 (기준선이 없으면 `npm run sim:baseline`).
2. 수치 수정 → `npm run sim && npm run sim:report` → `sim/reports/current/balance-compare.md`
   에서 전후 비교 확인 (사다리 눈금 §1 기준으로 판정).
3. 확정 시 `npm run sim:baseline`으로 기준선 갱신 + 이 문서 갱신 + 커밋.

## 8. 실험 이력 아카이브 (기각된 안)

- 난이도 배율 일괄 −0.1 (0.2~1.0): easiest 후반벽·hard 초반벽에 무효 → 원복.
- 적 지수 1.06/1.05: 봇 저활용(도구 미사용 등)에 맞춘 착시 균형 → 기각, 1.07 확정.
- 킬 보상 웨이브 스케일: 불필요 — 몹 수 증가(1.5/웨이브)가 이미 수입을 스케일.
- 티어드 XP 곡선(v2.6~v2.13): 만렙 불가 + 스왑 순환 봉쇄 → 플랫 100 복원.
- 봇 측: statTotal 체급컷·5보드 처칭·처칭 창 w42 — 전부 medium 회귀로 기각
  (상세: sim/README.md).
